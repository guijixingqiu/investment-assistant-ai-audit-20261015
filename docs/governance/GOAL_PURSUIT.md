# Goal Pursuit Governance

Use only for an explicitly named Owner goal. Ordinary authorized local changes
do not require this mode, Stage labels, or an envelope. Standing authority
covers the named scope until revoked; external publication and merge still
follow the Owner's delivery policy.

## Delivery package

When project_controller_handoff is active, its current_task in the actual
controller ROOT selects execution. local_goal / next_task and historical
snapshots do not override that selection. Without a controller, the legacy
local_goal / next_task relationship selects one bounded package.

A long product goal retains its full requirements while delivering coherent
complete user journeys. Each active package identifies behavior, scope, base,
ownership, completion criteria, necessary checks, cumulative repair effort and
next action. Owner-authorized independent implementation packages may proceed
in parallel; only actual shared dependencies and integration are serialized.
A report or provider failure blocks only dependent behavior. Repair on the
existing branch where applicable; do not reset effort by renaming a task.

Local development does not itself authorize push, Issue/PR publication or
messages. Use separately granted Owner coordination and independent ChatGPT
audit authority within its exact scope. Once a complete package works, perform
the smallest sufficient applicable checks; version-bound independent review
follows the reduced stage/risk cadence in AGENTS.md, not every local package or
installation. Reduce total code inspection rather than move it to the controller;
reuse unchanged evidence. Publish only when authorized. A test, screenshot or commit
alone never completes the user journey.

Record Owner intent, actual execution and the App Goal status separately.
A continuation request revokes an earlier pause within the requested scope;
an App Goal runtime failure does not revoke independent authorized work.
Only actual active Goal readback proves Goal mode is running. A scheduled
heartbeat is a separate follow-up mechanism, not proof of Goal activation.
Never edit internal app state or mark an unfinished goal complete to recreate it.

The current formal plan owns original twelve-step / B0-B5 / A01-A20 coverage.
Independent ChatGPT audits occur only at major-version checkpoints or explicit
Owner requests. A checkpoint represents a coherent product milestone or
substantial product/architecture change, not each feature candidate, repair,
commit, local integration, cross-module edit or time threshold. Small findings
accumulate for the next major version; Codex checks and fixes code locally.
The review asks whether implementation follows original needs/design, whether
governance is disproportionate or overengineered, and whether architecture and
technical choices fit a personal-use demo. Supply requirements, usable journeys,
important changes, reuse decisions, tradeoffs, gaps and necessary evidence,
not an undirected dump of code. Request directional risks, key deviations,
their impact and prioritized decisions. Naming, hashes, formatting and other
detail-level defects belong to Codex, not the external review agenda.
Preserve the original request/reply and a concise disposition; version identity
remains internal. Deduplicate sends; unknown sends require readback before retry.
Review opinions cannot silently replace Owner choices or add automatic gates.

## Coordination and lock

The controller holds the existing shared modification lock while mutating and
integrating the shared repository. Independent read-only probes may run in
parallel; only dependent work waits. Explicitly authorized implementation task
windows own non-overlapping worktrees and return commits for one integration
lane. They never receive the controller token or publish independently.

A busy lock blocks competing writes, not read-only inspection. If the controller
exits, writes stop; inspect host/PID/parent before requesting explicit stale-lock
recovery. Never steal or adopt the old token. Release the exact token at a safe
stop; do not hold a lock solely across an external review wait. No second lock
system and no reusable bootstrap exception.

## Evidence and closeout

Record implementation, integration, runtime and Owner acceptance separately,
bound to their exact object, commit, scope and evidence. Missing lanes remain
UNKNOWN. A waiver removes a waiting condition only; acceptance of V1 is not
acceptance of V2. Historical records are non-executable.

P1/P2 findings isolate affected behavior and trigger an authorized repair plus
focused checks. They do not require permission for each correction. Codex owns
the necessary exact-code review before an authorized merge. ChatGPT follows
the major-version boundary above; a small merge or corrective commit is not a
new external review trigger.
For an authorized merge, identify one PR, verify all applicable checks and
independent review on its exact head, then bind that head and squash method.
Head drift invalidates evidence, not standing Owner intent. Forbid auto-merge,
direct main pushes and Stage Runner merging. See AUTOPILOT for closeout.

## Product boundaries

AGENTS.md defines the advisory-only product, data and external boundaries.
The four-tab native client target and investment decision loop are requirements,
not presumed runtime achievements. A missing provider or offline physical
device blocks only its dependent lane; continue useful authorized local work.
